# 应用开通一期实现与验收

本实现以 APPLICATION_PROVISIONING_DATABASE_DESIGN.md 为目标模型，保留统一身份、应用产品、租户开通实例、应用 RBAC 和一次性授权码 SSO。

## 复核后的范围

- 本地学习默认 HTTP；DEV 回调允许 HTTP，但必须是管理员登记的精确地址，禁止通配、用户信息、片段和查询串。正式部署可自行配置 HTTPS。
- `platform-console` 是现有管理端；`learning-workbench` 是由 open-api 实际承载的学习工作台。bin-ai 仍为能力库，不伪造 AI 应用入口。
- 一期只初始化数据库内角色和授权，事务成功即可 ACTIVE。外部 AI 资源、计费、部门模型不在本期；今后涉及外部资源时再引入 Outbox。
- 关闭后恢复原开通实例，保留角色、授权和审计；时间窗实时判定，不依赖定时任务。
- 平台管理页面维护跨应用资源，但租户管理员只能维护本租户实例的成员和角色，不能开通其他产品或修改全局资源。
- 平台原 IAM API 固定在 platform-console；其他应用 RBAC 使用显式实例边界的应用 API。学习规模下应用权限实时查询，不维护可能失效的跨应用权限缓存。
- 旧 Token 在升级后失效，需要重新登录，不引入同时接受无受众 Token 的过渡漏洞。
- SSO 使用 256 bit 授权码、Redis 摘要键、60 秒有效期、原子消费、S256 PKCE、精确回调和后端客户端凭证。service_id 本身不是调用身份。
- Access Token 包含 aud、sid、tenantApplicationId 和 credentialVersion；网关实时验证会话和开通状态。工作台通过 BFF 的 HttpOnly 会话 Cookie 保存浏览器登录态，Token 只存在服务端。
- 单应用退出不影响平台；全局退出撤销当前平台会话及其子会话。租户、用户、应用或授权失效后所有旧会话实时拒绝；恢复状态也不复活被撤销的会话。

## 迁移和兼容

V4 创建应用与会话表；V5 回填已有租户和 IAM 数据、增加约束。保留历史 permission/menu 的 tenant_id 空列以兼容现有 MyBatis 模型，不作为授权依据。既有租户的 platform-console 实例使用租户 ID；其他应用使用独立雪花 ID。

新增/改密令牌将以 credential_version 失效，角色信息只用于展示，服务端每次重新计算权限。部署前备份数据库，不手工修改已有 Flyway 脚本。

## 验收路径

1. 平台管理员维护应用、客户端凭证和回调，给租户开通应用并指定初始应用管理员。
2. 平台管理员设置实例的 ALL/ASSIGNED 和开通时间窗；租户管理员维护本租户成员授权时间窗、应用角色和成员角色。
3. 用户在“我的应用”只看到可进入的应用；进入学习工作台，完成授权码回调并显示本应用权限。
4. 不同应用可以拥有同名角色和权限，但不能跨应用分配；平台 Token 不能访问应用 API。
5. 暂停、到期、关闭、撤销用户授权、改密、用户/租户禁用及退出使会话不可用；授权码重复兑换失败。
6. 管理端可以查询会话、强制下线和 SSO 成功/失败审计，记录中没有密码、授权码或 Token。


## 本地启动与完整操作路径

不要求配置 HTTPS，也不需要证书。请使用 MySQL 8、Redis 6.2+（授权码使用 GETDEL 原子消费）以及已有的 Nacos。

1. 先备份数据库，执行本目录下的 applications-preflight.sql（只读检查），确认没有迁移保留 ID 冲突和孤儿记录。V4/V5 由 platform-service 的 Flyway 按版本执行，不能把它们当作可重复手工导入的初始化脚本。
2. 使用 JDK 21 构建后同时更新 platform-service、admin-api、open-api、bin-gateway 和 bin-web。升级旧 Token 不再有效，请重新登录。所有签发/验证服务使用相同的 JWT_SECRET；网关与 API 使用相同的 GATEWAY_CONTEXT_SIGNING_SECRET，不在仓库保存其值。
3. 平台管理员登录后进入“应用管理 → 应用产品目录”，检查学习工作台的回调为 http://localhost:5173/api/open/workbench/callback，环境选 DEV。
4. 点击该应用“轮换凭证”，复制仅显示一次的凭证到 open-api 进程的 WORKBENCH_SSO_SECRET 环境变量，重启 open-api。WORKBENCH_PUBLIC_BASE_URL 默认 http://localhost:5173。如改用 127.0.0.1、其他端口或 Nginx 地址，必须同时修改该变量和精确回调白名单，保持发起页和回调同源，不能混用域名。
5. 在“租户管理”创建租户与管理员，已有租户没有管理员时使用“开通管理员”。到“应用管理 → 租户开通与授权 → 开通应用”，选择租户、学习工作台及该租户内的管理员账号。
6. 租户管理员使用该租户编码登录平台，进入“应用管理”，维护自己的应用角色与成员。其他普通用户在“我的应用”仅看到有准入资格的应用；应用管理员初始拥有该应用现有权限。
7. 点击学习工作台“进入应用”，应用后端建立 state 和 PKCE，平台确认页签发一次性授权码，open-api 后端兑换后跳转工作台。工作台显示账号、租户、实例、角色、权限与已接入菜单；“执行示例功能”由后端再次校验 workbench:execute。
8. “仅退出本应用”保留平台登录；平台退出撤销该次平台登录的所有子应用会话。在会话管理页面可强制下线；暂停/关闭应用、禁用身份、改密、变更成员/角色后，旧应用会话不可再用，需要从“我的应用”重新进入。
9. 执行 applications-postflight.sql 检查迁移后关联关系。数据库全量备份是迁移回退依据；MySQL DDL 不能假定完整事务回滚，不提供删表式自动回滚。

管理员编辑用户/租户资料也会保守地撤销相关会话；恢复身份不会复活旧会话。角色权限调整撤销该实例的应用会话。ALL 是准入策略，不是自动授予全部操作权限；其下禁用单个 sys_user_application 记录不会排除该成员，应改用 ASSIGNED 管理排除名单。

## 接入其他应用

应用产品目录、资源目录、租户开通、授权和会话管理均可复用。目录登记不自动生成业务前后端：新应用需实现自己的后端 SSO 发起/回调、服务端 Token 存储和权限校验，然后登记实际入口、精确回调及唯一 service_id。示例 workbench 只实现已编译的概览页，未实现的菜单显示为不可点击，不伪造业务页面。

网关内置 /admin/ 和 /platform/ 绑定 platform-console，/open/ 绑定 learning-workbench。新路由需在路由 metadata 中设置 applicationAudience 为产品 code，否则网关拒绝。/platform/internal/** 和 /internal/** 不允许通过网关访问。BFF 的白名单仅包含几个固定路径，BFF 自己校验服务端会话和 CSRF，不能给其他应用添加宽泛匿名通配路径。

本期为本地学习单实例实现：open-api HttpSession 存在进程内，重启需要重新进入应用，多实例部署前需接入共享会话存储；应用权限实时查询数据库，控制台旧权限缓存仍只服务 application_id=1。SSO 会话实时访问 platform-service，服务不可用时拒绝访问。HTTP 仍可被网络监听或篡改；本地运行不强制 TLS，但不能把这一配置当成公网安全部署方案。PKCE 与一次性授权码不能替代传输层保密。

数据范围仅提供“本租户本应用全部”和“本人”两种角色元数据；学习示例没有业务数据表，后续业务查询必须额外实施对应数据范围。未实现部门、AI 业务资源初始化、计费、跨进程 Outbox 和标准 OAuth/OIDC 完整协议，这些均属于设计的后续扩展，不计入本地一期交付。

## 验证与边界

- 根目录 mvn verify：编译、单元测试、H2 数据库事务/约束/SSO 集成测试，以及 BFF 控制器测试。H2 使用 V4 SQL 去掉 MySQL 存储语法，V5 外键边界在测试结构中对应验证；不能代替实际 MySQL 的 V1→V5 升级演练。
- 前端 vue-tsc、Vite build、ESLint 与 Vitest。e2e/application-harness.html 是开发服务器下的隔离页面夹具，可切换 ?view=mine、?view=sessions、?view=workbench；不包含真实账号、密钥，也不会进入生产构建入口。
- 本次已用隔离页面验证开通选择、管理员联动、长 ID/角色/权限回填、弹窗、会话与审计时间、工作台操作。未修改用户现有数据库，未声称完成真实 MySQL/Redis/Nacos 服务链路的联调。启动后按上面的九步运行即可进行真实环境验收。

安全参考：授权码重定向与 PKCE 采用 RFC 9700 的精确匹配和绑定原则（https://www.rfc-editor.org/rfc/rfc9700.html），本项目不宣称完整的 OAuth 授权服务器兼容性。
