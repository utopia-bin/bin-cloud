# 管理端修复与租户开通说明

## 本次范围

1. HTTP JSON 将超过 JavaScript 安全整数范围的 Long 输出为字符串，保留雪花 ID；分页数量等安全整数保持数值。日期输出包含时区。
2. Dubbo API 显式声明共享 BizException，避免提供者 ExceptionFilter 将业务错误包装成不透明 RuntimeException；管理端只透传已知业务错误，未知错误仍隐藏内部细节。包含真实 ExceptionFilter 和 STRICT Hessian2 测试。
3. 补齐租户、菜单、权限、字典、字典项、参数和短信发送的写操作审计，保留用户、角色和认证审计。登录成功使用返回身份归属租户，失败时使用请求中的租户编码解析归属；无法识别的租户仍记录为空，不将其归属到其他租户。参数默认屏蔽，日志截断长度包含省略号，日志故障不改变业务结果。
4. 前端修复列表接口分页、弹窗挂载、时间展示、表单空值提交、创建专属字段、字典选中空事件；移除参数值查询、无效状态筛选、可用项列表及无用文案。统一各页英文标题；登录页只保留居中表单。
5. 当前没有部门组织模型。角色仅接受 1（租户内全部）、4（仅本人），拒绝 2/3。dataScope 是业务数据授权预留字段，现有管理接口仍通过功能权限及租户隔离控制，并未在本次引入部门或通用行级本人过滤器。已有 2/3 值不自动扩大权限，编辑时须主动选择支持的值。

## 租户控制台闭环

- 新增租户必须填写 `adminUsername`、`adminPassword`，租户、管理员、`tenant_admin` 角色及权限关系在同一事务创建，失败全部回滚。
- 已有租户可点击“开通管理员”，对应 `POST /tenants/{id}/administrator`，需要 `platform:tenant:update`。只支持首次初始化；重复请求拒绝，不重置既有账号密码。
- 初始密码按当前平台强度策略验证并 BCrypt 加密，不返回或记录明文。请通过组织安全渠道交付，管理员可在个人菜单修改密码。
- 使用租户编码、管理员账号和密码登录，进入 `/dashboard`，可维护本租户用户、角色、字典、参数及查看日志。无授权账号有明确提示，不显示不可用快捷入口。
- 默认权限是明确允许列表，不含 `*`、租户管理、全局菜单修改、全局权限修改。服务端禁止为角色分配超过操作者自身授权范围的权限。
- 依赖现有 V1–V3 迁移和首次平台 bootstrap 导航。本次不更改数据库结构，不自动给已有普通用户提权，不自动修复被人为禁用或删除的全局权限/菜单。

## 与多应用设计的关系

本次完成现有平台控制台的租户初始化，不等于完成 `APPLICATION_PROVISIONING_DATABASE_DESIGN.md` 的多应用 SSO。
`sys_application`、租户应用实例、应用级 RBAC、可进入应用列表、一次性授权码、带 aud/sid 的令牌及应用会话撤销尚未实现，不能用现有平台 Token 直接替代这些边界。下一阶段需要一起完成表迁移、服务端鉴权、应用开通页面和跨应用隔离测试，再接入实际 AI 业务应用；不把 `bin-ai` 依赖模块当成可登录应用。

## 验证与发布

- JDK 21：`mvn verify`，173 项测试通过，0 失败、0 错误、0 跳过。包括雪花 ID、异常脱敏、Dubbo 异常传递、登录审计、租户初始化/回滚/重复开通、授权范围校验。
- 前端：类型检查、11 项 Vitest 测试、Vite 生产构建、ESLint 零警告通过。生产构建仍有既有主包大小提示。
- 浏览器在本地隔离 fixture 使用真实页面组件，检查 31 条权限按 10/10/10/1 展示、完整 ID、字典项新增、参数清空请求、日志日期及顶层弹窗、真实登录路由布局。
- 没有使用真实账号连接 Nacos/MySQL/Redis 环境做业务写入，不宣称已完成线上端到端验收。
- 发布时先更新 platform-service 与 admin-api（同步共享契约），再更新前端并刷新页面，避免旧页面内存里已失真的 ID 继续被使用。若仍有错误，使用服务端日志排查，不能向前端直接返回 SQL、堆栈或敏感信息。
